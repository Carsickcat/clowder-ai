上下文断裂

阶段割裂

结论不可追溯

“看起来没问题”没有绑定 source snapshot、query digest、人工决策与报告快照。

产品定义

NOVA 不是替人拍板，
而是把事实、未知与决策边界
放到同一张桌面上。
一句话描述变更 → 生成可审阅方案 → 创建独立 Case → 服务端只读执行 → 证据化评估 → 人工接受并固化不可变报告。

单屏工作台

页面始终回答三个问题

我在巡检什么？当前结论是什么？下一步应该做什么？

变更上下文 + 三阶段旅程服务 / 版本 / 变更单 / 当前进度
作业与 Case复用方案，但每次执行保持独立
结论与证据中心指标、评估、A/B、覆盖缺口、最终报告
CLAW 巡检搭档解释生成依据与证据，不伪造状态
执行与决策时间线Run、人工动作和报告固化形成连续记录

端到端用户旅程

从一句话到一份不可变报告

01描述变更

输入服务、版本、变更意图与只读数据源。

02生成方案

结合拓扑、规则与历史形成候选项和覆盖缺口。

03人工编排

选择检查项；必选项缺失必须填写 waiver。

04三阶段执行

变更前、灰度、变更后均由服务端读取证据。

05证据化评估

区分事实、假设、未知与建议，输出 A/B。

06人工接受

最新完成态通过后，固化证据与决策快照。

可信边界

浏览器发起意图，服务端拥有事实

变更上下文service / version / changeId / topology provenance
只读观测source snapshot / observedAt / query digest
机器评估threshold / verdict / coverage / A-B consistency
人工决策actor / note / accepted run / immutable report

以下情况一律 fail closed

  • 观测过期或来源中断
  • source / query 口径不一致
  • required 检查缺失且没有 waiver
  • 存在未解释的 unknown 或覆盖缺口
  • 不是最新完成态、通过的变更后 Run
