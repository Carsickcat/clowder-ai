# 变更巡检产品收敛结论

## 结论

停止继续扩写 NOVA Ops 的七菜单大盘。本轮交付一个完整、可走通的“变更巡检”纵向切片：

> 用户用一句人话提出变更风险问题，系统生成可审阅的巡检方案；用户确认后完成变更前准入、灰度阶段持续验证和变更后验收，最后得到可追溯的风险结论与报告。

这不是把旧 `Inspection` 页面翻译成中文，而是把产品主对象从“菜单里的能力”改为一个 `ChangeInspectionCase`。

## 多猫独立讨论的共识

- 丢丢：产品顺序应为用户旅程 → 原子能力 → 交互分工 → 页面投影。
- 烁烁：今晚只做一条巡检旅程；对话是创建入口，页面是结果和决策入口。
- Terra：必须有可比性契约；预期会变化的指标不能机械复用旧基线，缺失时应是 `不可判定`。
- Luna：变更前/中/后是同一个 Journey，不是三个产品；Verification 是一次特殊目的的 Run，不应再成为顶级菜单。
- GPT-5.4：持久状态应收敛为 Case、Policy/Plan、Baseline、Run、Finding、Decision、Report。

## 差异与取舍

### 是否保留“案件列表”和“报告中心”

首轮可用切片先实现单一 Case 工作区，用于验证完整任务；operator 后续补充了高频复用场景，因此在同一工作区增加轻量“作业平台”。它展示已固化方案和最近运行摘要，但不复制历史 Run，也不发展成第二套执行产品。

### Claw 能否直接执行放量

不能。Claw 可以生成草案、解释结果、提出建议；执行巡检、确认准入、继续放量、发布最终报告都需要页面上的显式动作并写入决策记录。

### 自动化应该做到哪里

演示中自动生成检查项、编排任务和生成报告；涉及生产放量的动作只模拟状态推进，并明确标记为演示数据。真实发布平台集成不在本轮范围。

## 产品原子能力

1. `理解意图`：解析服务、版本、环境、变更窗口和风险目标。
2. `生成方案`：结合已部署指标生成检查项、阈值、基线和执行频率。
3. `确认方案`：展示覆盖、缺口与不可判定条件，允许人工确认。
4. `执行巡检`：产生不可变 Run 与 Evidence。
5. `比较判定`：变更前准入、canary/control、前后基线比较。
6. `持续编排`：按灰度阶段或时间计划执行。
7. `风险决策`：通过、风险、不可判定、阻断。
8. `报告与解读`：生成快照，给出结论、证据、影响和下一步。

## 交互分工

| 用户目标 | Claw 对话                          | 页面                                            |
| -------- | ---------------------------------- | ----------------------------------------------- |
| 复用巡检 | 解释已载入作业，不自动执行         | 选择历史作业、审阅固化方案和最近运行摘要        |
| 发起巡检 | 理解自然语言，补齐上下文，生成草案 | 展示解析结果、计划和数据覆盖                    |
| 修改方案 | 接受“增加库存一致性检查”等意图     | 精确确认检查项、阈值和频率                      |
| 查看进度 | 回答“现在卡在哪里”                 | 展示阶段、Run、证据新鲜度和门禁                 |
| 解读风险 | 用人话解释结论和证据               | 保留原始指标、比较窗口和 Decision Record        |
| 推进变更 | 提出建议，不直接执行               | 唯一主动作：确认准入/开始灰度/继续观察/完成验收 |

## 产品视图

只保留一个工作区：

1. 左侧作业平台：可复用检查方案、最近运行摘要、新建巡检入口。
2. 顶部上下文：服务、版本、环境、变更编号、当前阶段、演示数据。
3. 三阶段旅程：变更前准入 → 灰度持续验证 → 变更后验收。
4. 中央决策面：当前最重要结论、证据、检查项与唯一主动作。
5. 右侧 Claw：对话、解释和建议，始终说明“不会代替你执行生产动作”。
6. 底部/抽屉报告：Run 时间线、决策记录和最终报告快照。

## 失败模式契约

- 基线缺失或不可比：`不可判定`，禁止自动准入。
- 指标数据过期：展示新鲜度并阻断推进。
- 灰度异常：暂停在当前阶段，要求查看证据或人工记录决定。
- 执行中切换作业：拒绝切换，防止当前 Case 的证据被无提示丢弃。
- 用户刷新页面：本原型暂不承诺持久化；界面必须明确“演示数据”。
- 移动端：保留当前决策、阶段和主动作；复杂证据改为纵向折叠，不使用缩写导航。

## 三件套沉淀检查

- ADR：本轮不新增独立 ADR；这是可逆原型收敛，拒绝的七菜单方案写入 Feature Spec。
- Lesson：把“结构存在 ≠ 用户能理解”写入本轮体验合同，作为回归测试。
- Operating rule：产品设计必须先声明 Journey、Atomic capabilities、Interaction split，再允许出现顶级导航；作为本轮 Feature Spec 的 Product Gate。
