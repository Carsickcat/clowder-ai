# NOVA 变更巡检：从变更上下文到可审计决策

> **受众**：内部产品负责人、研发负责人、SRE / 发布负责人
> **场景**：产品方案与最小实现对齐；一条 `payments-router v3.18.0 / CHG-23841` 变更贯穿全稿
> **风格 preset**：自定义 NOVA operational cockpit；严格继承 `75d991e` 深色高保真
> **视觉**：深海军蓝背景、低饱和电光蓝主动作、薄荷绿通过态、珊瑚红风险态、琥珀色覆盖缺口
> **页数**：8 页，16:9 横版；第一页直接进入用户时序，无独立封面
> **原则**：每页都回答“输入 → 核心处理 → 输出 → 用户价值 → 失败如何诚实暴露”
> **AI 边界**：规则产生事实门禁；AI 负责语义归并、根因假设、风险排序与证据化建议；人保留生产决策权

## P2：巡检项生成｜从变更语义与拓扑中发现“应该检查什么”

```text
┌══════════════════════════════════════════════════════════════════════┐
║ 左 38%：[输入与影响扩散]                  右 62%：[候选项包]          ║
╠═══════════════════════════════╤══════════════════════════════════════╣
║ [文字] 用户：巡检 payments-   │ REQUIRED                            ║
║ router v3.18.0 是否可灰度     │ ┌ p95 延迟                          ║
║                               │ │ 原因：核心同步链路 + 历史排队风险 ║
║ [数据] CHG-23841              │ │ 来源：变更流 + payment-gateway   ║
║ 路由策略配置变更              │ └ 阶段：前 / 灰 / 后                ║
║                               │                                      ║
║ [拓扑]                        │ RECOMMENDED                         ║
║ payments-router               │ ┌ 支付成功率 / 下游失败率           ║
║   ├─sync→ payment-gateway     │ └ 理由、数据源、阈值、窗口齐全      ║
║   ├─db→ payment-ledger        │                                      ║
║   └─async→ audit-consumer ?   │ COVERAGE_OMISSION                   ║
║                               │ audit-consumer 暂无只读观测连接器   ║
║ [历史] Playbook + 故障记录    │ 不计健康覆盖；需 waiver + 治理项    ║
╚═══════════════════════════════╧══════════════════════════════════════╝
```

**输入**：自然语言意图、结构化变更流、带方向和类型的单跳依赖快照、历史 Playbook / 故障规则。

**输出**：`CandidateSet`，每项包含 `required/recommended/optional`、生成理由、EvidenceRef、数据源、阈值、适用阶段和置信状态；另产出独立 `CoverageOmission[]`。

**价值**：把“靠经验想到几个指标”变成可复查的影响分析；历史模板只提供候选，不复用旧证据。

**失败处理**：服务、版本或环境无法解析时要求澄清；图谱过期或关键依赖无数据源时显式 UNKNOWN / COVERAGE_OMISSION，不生成绿色结论。

**视觉指引**：
- 页面类型：左输入/右输出双栏；背景保持 cockpit 深色
- `required/recommended/optional` 用三级语义标签；required 使用高亮蓝边
- `audit-consumer` 使用琥珀色虚线节点，强调“看见缺口本身就是价值”
- 不画无限拓扑；只显示与本次变更可解释相关的单跳关键依赖

## P3：任务编排与复用｜把候选项固化成可审计 Revision

```text
┌══════════════════════════════════════════════════════════════════════┐
║ Playbook：支付路由灰度巡检                       Revision DRAFT V3   ║
╠══════════════════════════════════════════════════════════════════════╣
║ [表格]                                                               ║
║ 级别        巡检项        阶段        规则 / 基线          操作       ║
║ REQUIRED    p95 延迟      前·灰·后    稳定组 +10% / 10m    编辑       ║
║ REQUIRED    支付成功率    前·灰·后    ≥99.70% / 10m        编辑       ║
║ RECOMMENDED 下游失败率    灰·复验     无新增失败依赖       编辑       ║
║ OPTIONAL    审计积压      后          数据源待接入          waiver     ║
╠══════════════════════════════════════════════════════════════════════╣
║ [流程] CandidateSet → SRE 增删改 → 校验数据源/基线 → 冻结 Revision  ║
║                                                                      ║
║ required 删除：必须填写 waiver reason                               ║
║ 首次 Run 后：禁止改写；变更只能创建 V4 + successor Case             ║
╠══════════════════════════════════════════════════════════════════════╣
║ [主动作] 确认 Revision 并执行变更前巡检                              ║
└══════════════════════════════════════════════════════════════════════┘
```

**输入**：CandidateSet、灰度阶段策略、数据源能力、SRE 调整和 waiver。

**输出**：不可变 `PlaybookRevision`；固化检查定义、优先级、阶段、阈值、窗口、基线、频率、数据源和门禁策略。

**价值**：同类变更可复用策略，但每个 Case 重新抓取依赖快照并做 drift check。

**失败处理**：required 被删除却无 waiver、基线不可比、数据源 scope 不匹配或关键依赖漂移时进入 `BLOCKED_REVIEW_REQUIRED`。

**视觉指引**：
- 页面类型：高保真中央“巡检方案”工作面放大版
- 表格采用细边框，状态与操作列保持简洁；不画通用自由 DAG
- Revision 锁定前后用明显的 DRAFT → LOCKED 视觉转换
- 主动作按钮沿用 `75d991e` 的电光蓝样式

## P4：执行与证据采集｜AI 不能成为事实来源

```text
┌══════════════════════════════════════════════════════════════════════┐
║ [阶段轨道] 变更前 ✓       灰度 25% · 风险       变更后 · 待执行     ║
╠══════════════════════════════════╤═══════════════════════════════════╣
║ [执行链]                         │ [证据质量]                        ║
║ 外部阶段标记：25%                │ SourceSnapshot                    ║
║        ↓                         │ prometheus-prod-readonly          ║
║ StageRun RUN-002                 │ window 10:08–10:18                ║
║        ↓                         │ freshness ✓ query digest ✓        ║
║ 只读 ObservabilitySource         │ comparability ✓ coverage 4/5      ║
║        ↓                         │ omission: audit-consumer          ║
║ CheckResult[]                    │                                   ║
║        ↓                         │ [状态分离]                        ║
║ deterministic evaluator         │ Run: COMPLETED                    ║
║                                  │ Verdict: RISK                     ║
║ p95 263ms · +17.8% · RISK        │ Decision: HOLD                    ║
╠══════════════════════════════════╧═══════════════════════════════════╣
║ 浏览器不能提交 observation/source/verdict；NOVA 不执行放量或回滚   ║
└══════════════════════════════════════════════════════════════════════┘
```

**输入**：锁定 Revision、当前阶段、环境绑定的只读数据源。

**输出**：不可变 `Run + SourceSnapshot + CheckResult[]`；执行状态、机器 verdict 和人工 decision 分开记录。

**价值**：报告和 AI 解读都建立在可验证证据上；模型不可用时规则执行仍可工作。

**失败处理**：缺数据、过期、查询 digest 不匹配、部分观测或 A/B 不可比统一为 UNKNOWN；连接器故障为 Run FAILED，绝不回退演示数据。

**视觉指引**：
- 页面类型：流程 + 证据质量双栏；左侧像运行管线，右侧像审计卡
- p95 风险使用珊瑚红大数字 `+17.8%`
- 三套状态用彼此分离的小卡片，不把 ERROR/WARN/FAIL 混成一个分数

## P5：报告生成｜每个阶段都是不可变事实快照

```text
┌══════════════════════════════════════════════════════════════════════┐
║ [横向时间线]                                                         ║
║ AdmissionReport ── 25% Risk ── Verification ── 100% Stable ── Post ║
║ PASS              RISK          PASS             PASS          PASS  ║
╠══════════════════════════════════╤═══════════════════════════════════╣
║ [阶段报告：25%]                  │ [最终 A/B 报告]                   ║
║ p95 +17.8% · 支付成功率稳定      │ 业务健康：范围内 PASS             ║
║ 风险：连接池排队                 │ 依赖影响：治理后无异常退化        ║
║ 证据：RUN-002 / 3 个查询引用     │ 观测完整度：4/5 + 1 omission      ║
║ 决策：HOLD                       │ 前后 p95：201ms → 198ms           ║
║                                  │ 未关闭：audit-consumer 接入治理   ║
╠══════════════════════════════════╧═══════════════════════════════════╣
║ 报告骨架由结构化事实生成；AI narrative 是可选投影，不改写 verdict  ║
└══════════════════════════════════════════════════════════════════════┘
```

**输入**：Revision、Run、CheckResult、SourceSnapshot、Finding 和 DecisionRecord。

**输出**：每阶段 `ReportSnapshot` 与最终跨阶段 `FinalReportSnapshot`；报告固化 runIds、decisionIds、规则版本、证据引用和未关闭风险。

**价值**：用户可以从任一阶段报告回到当时证据；最终报告天然包含变更前后 A/B，而非只展示当前指标。

**失败处理**：报告冻结后禁止追加 Run 或改写证据；需要复验时创建新 Run 和 successor snapshot。

**视觉指引**：
- 页面类型：顶部横向时间线 + 下方阶段/最终报告双栏
- 直接借用 `75d991e` report 卡片、指标卡和时间线语言
- 最终结论用薄荷绿，但 `1 COVERAGE_OMISSION` 保持琥珀色可见

## P6：评分与智能解读｜AI 的价值是减少判断成本，不是写漂亮总结

```text
┌══════════════════════════════════════════════════════════════════════┐
║ [上层：确定性门禁]                                                   ║
║ 阈值 · 新鲜度 · 覆盖 · 查询一致性 · 基线可比性                     ║
║                 → PASS / RISK / UNKNOWN                              ║
╠════════════════════════════════════╤═════════════════════════════════╣
║ [左：四维评估]                     │ [右：CLAW 证据化解读]            ║
║ 策略门禁       RISK                │ 已证实：p95 +17.8%               ║
║ 证据质量       HIGH                │ 可能根因：灰度实例连接池排队     ║
║ A/B 可比性     VALID               │ 仍需验证：调整后 10 分钟窗口     ║
║ 残余风险       MEDIUM              │ 建议：80→120，保持 25% 并复验   ║
║                                    │ Evidence: RUN-002 / QUERY-17     ║
╠════════════════════════════════════╧═════════════════════════════════╣
║ 关键项 RISK / UNKNOWN 不会被大量绿色项平均成“87 分、建议通过”      ║
└══════════════════════════════════════════════════════════════════════┘
```

**输入**：结构化报告、规则结果、ChangeContext、ImpactScope、历史故障和证据引用。

**输出**：`AssessmentSnapshot`，包含事实摘要、风险优先级、根因假设、置信度、治理提案、验证条件和 EvidenceRef。

**价值**：AI 主动发现漏检风险、归并多指标异常、解释为什么不能下结论，并把治理建议变成可验证提案。

**失败处理**：模型不可用时保留规则报告并标注“AI 解读不可用”；根因永远标为假设，不能冒充已证实因果。

**视觉指引**：
- 页面类型：双层评估架构；确定性门禁在上，四维评估与 CLAW 在下
- 不使用仪表盘式总分圆环；使用四条语义状态轨道
- EvidenceRef 以小号代码标签显示，体现可追溯性

## P7：一屏交互｜原子能力由阶段串联，用户不需要自己拼产品

```text
┌══════════════════════════════════════════════════════════════════════┐
║ payments-router v3.18.0 │ CHG-23841 │ 25% 灰度 │ 当前：HOLD        ║
╠══════════════════════════════════════════════════════════════════════╣
║ ① 变更前准入 ✓  ───── ② 灰度持续验证 RISK ───── ③ 变更后验收     ║
╠══════════════════════════════════════════════╤═══════════════════════╣
║ [中央权威工作面]                             │ [CLAW]                ║
║ 当前结论：暂停在 25% 灰度                    │ 解释证据              ║
║ p95 +17.8%｜支付成功率稳定｜覆盖 4/5         │ 提出治理与复验条件    ║
║ 风险定位：连接池排队                         │ 自然语言→结构化提案   ║
║                                              │ 不直接改变产品状态    ║
║ [唯一下一步] 记录处置                        │                       ║
╠══════════════════════════════════════════════╧═══════════════════════╣
║ [时间线] Admission PASS → 25% RISK → 处置 → Verification PASS       ║
║           每个节点可打开对应阶段报告与原始证据                      ║
└══════════════════════════════════════════════════════════════════════┘
```

**交互原则**：顶部固定变更上下文和三阶段；中央始终显示权威结论与唯一下一步；右侧 CLAW 生成、解释、追问；底部时间线保留全部 Run、风险、处置、复验、决策与报告。

**状态矩阵**：loading / empty / draft / ready / running / risk / unknown / failed / completed；桌面与 390px 移动端都必须能完成黄金路径和一个非快乐路径。

**失败处理**：CLAW 的状态变化请求必须先变成结构化 proposal，再由用户在中央工作面确认；连接失败时进入 degraded 并禁用命令，不回退 fixture。

**视觉指引**：
- 页面类型：接近真实产品高保真的一屏大图，布局与 `75d991e` 相同
- 页面右侧明确安全提示“生成与解释，不执行生产动作”
- 时间线风险/复验节点使用红绿对照，不隐藏旧风险

## P8：最小可运行纵切与演进路线

```text
┌══════════════════════════════════════════════════════════════════════┐
║ 一期｜明早可运行                    二期｜真实变更中      三期｜治理  ║
╠═══════════════════════════════╤══════════════════════╤═══════════════╣
║ ChangeContext                │ 电子流/服务目录      │ 责任人与到期  ║
║ 单跳 ImpactSnapshot          │ 灰度阶段事件         │ 外部工单链接  ║
║ CandidateSet + omission      │ StageRun / 报告      │ 审批策略      ║
║ Playbook Revision            │ Revision drift       │ 受限调度      ║
║ Admission + Post Run         │ 历史匹配与复发分析   │ 跨 Case 治理  ║
║ A/B Report + Assessment      │                      │               ║
╠═══════════════════════════════╧══════════════════════╧═══════════════╣
║ [安全边界] 只读隔离数据源｜AI 无 verdict authority｜不控制发布/回滚 ║
║ [产品承诺] 过期图谱、缺失遥测、不可比数据永远不会被包装成绿灯       ║
└══════════════════════════════════════════════════════════════════════┘
```

**一期终态**：用户可以输入变更意图，看到基于变更与单跳拓扑生成的分级候选项，调整并冻结 Revision，执行变更前/后 Run，查看阶段与 A/B 报告，并获得带证据的风险解读。

**明确不做**：自由 DAG、生产发布控制器、自动回滚、多跳无限拓扑、模型生成观测或 verdict。

**视觉指引**：
- 页面类型：三列路线图；一期占页面约 50%，二三期各 25%
- 一期用电光蓝高亮并标注“MINIMUM RUNNABLE SLICE”
- 底部两条宽幅安全/产品承诺使用深色高对比条
