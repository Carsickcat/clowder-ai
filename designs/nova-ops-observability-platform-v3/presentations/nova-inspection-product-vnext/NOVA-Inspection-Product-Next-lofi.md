# NOVA AI 变更巡检：产品功能与用户旅程

> **受众**：产品负责人、运维负责人、发布负责人
> **场景**：内部产品方案讲解；用一条 `payments-router v3.18.0` 灰度变更串完整流程
> **风格 preset**：自定义 NOVA 高保真；深海军蓝、低饱和蓝、薄荷绿、风险珊瑚红
> **页面真相**：严格以 `NOVA-Ops-Intelligence-Standalone-75d991e.html` 为视觉和旅程母版
> **内容取舍**：只讲产品能力、页面操作和用户得到的结果；不讲路线图，不展示内部设计约束，不做“有 AI / 没 AI”对比
> **AI 边界**：AI 生成候选和解释证据；规则产生判定；人确认方案、阶段和治理决定
> **页数**：10 页

## P3：怎么开始 — 复用作业或直接告诉 CLAW

```text
选择“支付路由灰度巡检” ─┐
                         ├─▶ 载入服务 / 版本 / 门禁草稿
“巡检 payments-router    │
 v3.18.0 能否灰度发布” ──┘
```

- 作业只复用检查策略，不复用历史证据。
- CLAW 识别服务、版本、变更意图；信息不足时要求补充，不猜测。
- 结果进入中间“巡检方案”区域供用户审阅。

## P4：巡检项生成 — AI 把变更上下文变成有理由的候选

```text
服务与版本 + 单跳依赖 + SLO/指标 + Runbook + 历史风险
                          ↓
┌ 候选巡检项 ────────────────────────────────────────┐
│ 请求延迟 │ 原因：核心同步链路变更 │ 来源：依赖快照 │
│ 错误率   │ 原因：灰度门禁          │ 来源：SLO      │
│ 下游依赖 │ 原因：checkout-api 变更 │ 来源：变更说明 │
└────────────────────────────────────────────────────┘
覆盖：看见什么 / 为什么选择 / 没覆盖什么
```

**视觉指引**：候选项直接画在高保真的“系统准备检查什么”面板中；AI 价值通过每一行的理由和来源体现，不另做 AI 宣传页。

## P5：巡检项编排 — 在现有方案区增删改并冻结版本

```text
巡检方案 V2                                      [编辑]
┌ 检查项 ─────┬ 阶段 ─────────┬ 阈值 / 窗口 ──────┐
│ 请求延迟     │ 前 / 灰 / 后  │ 基线 +10% / 10m  │
│ 支付成功率   │ 前 / 灰 / 后  │ ≥99.70% / 10m    │
│ 下游失败率   │ 灰 / 复验     │ 无新增失败依赖    │
└──────────────┴───────────────┴────────────────────┘
[＋添加巡检项] [编辑] [删除]    [确认方案并执行变更前巡检]
```

- 草稿中可增删改检查项、阈值、频率、窗口、基线和适用阶段。
- CLAW 可以建议合并重复项、补齐覆盖缺口，但不直接发布。
- 用户确认后 Revision 锁定；执行开始后不覆盖历史方案。

## P6：变更前准入 — 先建立可比基线

```text
阶段 1 变更前准入
基线可比性校验 → 执行 5 项检查 → 阶段报告
PASS：可以进入 25% 灰度
UNKNOWN：缺数据 / 过期 / 不可比，阻断下一步
```

**视觉指引**：使用高保真“当前结论 + 方案 + 下一步”结构；突出唯一按钮“批准进入 25% 灰度”。

## P7：灰度持续验证 — A/B 对比、风险治理与复验

```text
灰度 25% vs 稳定 75%（同一窗口）
P95 延迟 +17.8%  →  暂停在 25% 灰度
        ↓
CLAW 解释风险 + 建议治理措施
        ↓
用户记录处置 → 新 Run 复验 → 继续到 100%
```

**视觉指引**：复用高保真的红色风险结论、三张指标卡、风险定位卡和底部时间线；旧风险 Run 必须留在时间线中。

## P8：变更后验收 — 生成阶段报告与最终报告

```text
变更前基线 ─┐
灰度风险/复验├─▶ 最终 A/B → 不可变报告快照
100% 稳定 ──┤             ├ 全部 Run
变更后 15m ─┘             ├ 风险与处置
                           └ 人工决策
```

**视觉指引**：复用高保真“本次变更未发现异常退化”、最终报告卡和五次 Run 时间线。

## P9：报告解读 — CLAW 在同一屏回答操作问题

```text
用户：为什么最终可以继续放量？
CLAW：
1. 发生了什么：25% 灰度曾出现延迟风险
2. 如何处理：连接池调整后复验恢复
3. 为什么通过：全量与变更后指标均在阈值内
4. 还有什么未知：列出未覆盖依赖与数据缺口
5. 接下来做什么：生成治理项与复验建议
   [RUN-002] [RUN-003] [FND-001] [RPT-001]
```

- 规则和证据决定 PASS/WARN/FAIL/UNKNOWN。
- CLAW 负责跨阶段归纳、风险解释、治理建议和证据引用。
- 治理建议只能记录，不能执行发布、放量或回滚。

## P10：完整用户旅程 — 一个页面完成七个动作

```text
选择作业 / 描述需求
        ↓
AI 生成候选巡检项
        ↓
用户增删改并冻结 Revision
        ↓
变更前准入 → 灰度 A/B → 风险治理 → 复验
        ↓
变更后验收 → 最终报告 → CLAW 解读
```

**收口文案**：用户得到的不是一份自动生成的文字报告，而是一条从“为什么检查”到“为什么得出结论”都可追溯的巡检证据链。

## HTML 制作合同

- 单文件、内联 CSS/JS、无网络请求；键盘、触摸、全屏、打印、390px 手机可读。
- 主视觉和文案必须来自 75d991e 高保真：`作业平台`、`当前任务`、`当前结论`、`Claw 对话`、三阶段、`执行与决策记录`。
- 至少三页直接使用 75d991e 实际页面截图或同源局部放大，不重画另一套产品。
- 不出现“当前 connected”“AI 增强目标”“没有 AI / 有 AI”“不做多级左树”“Phase / 路线图”等内部讨论表达。
- AI 能力嵌入具体用户动作：生成候选、解释理由、补齐覆盖、解读报告、给出治理与复验建议。
- 权威边界保持：只读观测、失败关闭、证据不可变、AI 不改 verdict、不执行生产动作。
