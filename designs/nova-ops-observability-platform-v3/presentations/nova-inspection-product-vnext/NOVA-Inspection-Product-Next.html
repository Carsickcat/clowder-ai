HOW USERS WORK TODAY

当前 connected：六个动作完成可审计闭环

先把已经能用的产品讲清楚，再说明 AI 往哪里增强；不把目标体验包装成现状。

01填写作业、服务、只读查询和阈值
02保存作业与 revision 1
03填写变更编号/版本，新建独立 Case
04选择执行阶段，执行只读巡检
05查看 AUTHORITATIVE RUN 与来源
06记录人工接受并固化报告
当前已具备：单巡检项闭环手工填写 query / threshold；持久化 Job、Revision、Case、Run、Decision、不可变报告；connected 页面暂无 CLAW。
AI 增强目标：多巡检项生成与解读在同一工作区内增加候选生成、多巡检项编排、阶段对比与报告解释，不改变当前服务端权威边界。
页面关系AI 不是另一套产品，也不是另一条导航；它服务于现有 Revision 草稿和 Report 阅读。

WHY AI

AI 的价值，不在替规则打分

查询与阈值判断本来就应该确定性执行。AI 的独特价值，是处理散落在依赖、文档、历史和多阶段证据里的语义劳动。

没有 AI

专家手工完成两次“翻译”

1读服务依赖、SLO、runbook、变更说明和历史事故，判断需要查什么。
2把业务风险手工翻译成 query、阈值、窗口与阶段。
3逐条读多阶段结果，再手工关联依赖影响、写报告与治理建议。

产品仍能工作，但质量依赖个人经验，设计和解读成本会随服务复杂度快速上升。

有 AI

上下文归并 + 证据化解释

1依赖上下文归并：把拓扑、SLO、runbook、变更和历史统一成带来源的上下文包。
2自然语言转检查草稿：生成检查定义、阶段、阈值依据与候选项生成理由。
3对权威结果做报告事实摘要、异常关联、风险解释、治理建议和不确定性披露。

AI 降低设计与阅读成本，但每个输出都必须有证据引用，不能成为权威结果。

规则负责判定 · AI 负责把上下文变成候选、把证据变成解释 · 人负责发布与接受

AI CAPABILITY 01 · INPUT

巡检项生成：先构建“为什么要查”的上下文

AI 不是看到依赖名就猜指标，而是把多源材料归并成一个带 provenance、时效和缺口的 Inspection Context Pack。

A

用户动作

在现有作业区选择服务、环境与变更；点击“生成巡检项草稿”，或用自然语言补充这次变更的意图。

输入不完整时：停止自动生成，并在首屏展示 omissions；允许手工继续，但标记“拓扑覆盖未知”。
服务与依赖快照单跳调用、方向、关键度、capturedAt、scope、omissions
SLO 与指标目录成功率、延迟、饱和度、容量、数据质量契约
Runbook 与告警规则已知故障征兆、排查顺序、指标含义、团队约定
变更上下文版本说明、变更范围、组件差异、期望影响
历史巡检与事故曾经失败的检查、重复风险、已验证治理措施
连接器能力当前可查询的数据源、只读 scope、freshness 与限制
Inspection Context Pack输入事实 + 来源引用 + 快照时间 + 覆盖范围 + 未覆盖项；作为候选生成的唯一上下文。

AI CAPABILITY 01 · OUTPUT

候选巡检项必须告诉用户：查什么、为什么、没覆盖什么

AI 产物不是一串指标名，而是一组可审阅的检查草稿。只有用户纳入 Revision 并发布后，它才进入执行真相。

B

AI 输出合同

1检查对象 + 推荐阶段 + query 草稿 + 窗口
2阈值依据 + 候选项生成理由 + 依赖路径
3证据来源 + 置信度 + 检查覆盖缺口

用户可添加、删除、编辑或拒绝候选；拒绝理由可沉淀为后续生成上下文，但不会修改历史 Revision。

AI CAPABILITY 02 · PIPELINE

报告生成：先冻结事实，再让 AI 组织解释

AI 只能读取服务端产生的 Run、CheckResult、Evidence 与 Comparison。任何摘要、关联和建议都引用原始证据，且不能覆盖机器 verdict。

确定性事实层

服务端权威证据

Run / CheckResult / observedAt / window
queryDigest / source snapshot / freshness
ComparabilityContract / PASS-WARN-FAIL-UNKNOWN
→
AI 解释层

报告事实摘要与关联

报告事实摘要：哪些指标、哪些阶段发生变化
异常关联：异常与服务依赖/变更组件的可能联系
风险解释、治理建议、不确定性与证据引用
→
用户决策层

审阅并固化

区分“确定性事实”与“AI 推断”
确认接受、阻断、豁免或复验
记录人工接受并固化报告
AI 不生成观测值 · AI 不决定 PASS / FAIL · AI 不覆盖证据 · 人负责发布与接受

AI REPORT EXPERIENCE

报告解读不是“写一段总结”，而是回答五个操作问题

发生了什么、影响谁、为什么重要、先做什么、还有什么不知道。每个答案都能点回 Run 和证据。

PRODUCT CAPABILITY MAP

用户最终得到：一套控制台，两段 AI 增强

NOVA 的底座仍是可审计的只读巡检控制平面；AI 让“设计巡检”和“读懂报告”不再完全依赖专家手工劳动。

01 · 当前

可复用巡检控制台

保存为可复用作业、版本化 Revision、新建独立 Case、同屏执行阶段。

02 · AI 增强

巡检项生成

归并依赖、SLO、runbook、变更与历史，生成有理由、有来源、有缺口的候选。

03 · AI 增强

巡检项编排

在现有 Revision 区增删改多巡检项、阶段、query、阈值和窗口，发布后冻结。

04 · 当前

只读权威执行

执行只读巡检，服务端生成观测、时间、queryDigest、verdict 与不可变证据。

05 · AI 增强

报告生成与解读

对多阶段事实做摘要、异常关联、风险解释、治理建议、不确定性和证据引用。

06 · 当前 + 增强

人工治理闭环

人审阅候选、发布 Revision、记录决定、创建复验并固化不可变报告。
