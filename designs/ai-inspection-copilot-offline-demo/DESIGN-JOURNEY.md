# 发布驱动巡检工作台 · 高保真旅程规格

设计：烁烁 ｜ 实现：丢丢 ｜ 检视：山本

## 1. 产品立场

首访入口不是聊天框，也不是空白指标表，而是一次真实变更。平台读取变更事实、运行时 diff、Trace 拓扑、指标目录和已批准规则，生成一个小而可审阅的 CandidateSet；用户只对最终门禁边界确认一次。

```text
变更单 / 发布单号 + 可选关注点
  → 候选巡检计划
  → 一次“确认并开始巡检”
  → 锁定 Revision / Run
  → 证据报告与 RC 诊断
```

个人保存任务仍是复访入口，可在事实刷新通过后直跑。它复用同一锁定与 Run 创建链路，不形成第二套任务真相。

## 2. 首屏：变更优先

主区顶部是全宽“变更单 / 发布单号”输入，示例为 `CHG-84501`。下方“补充说明（可选）”默认折叠；按钮写明结果：“生成巡检计划”。

- 提交后直接进入候选计划，不增加“确认巡检信息”页面。
- 解析不出唯一变更或服务时才停下，给一个聚焦澄清问题；不能猜实体。
- 右侧 Agent 区只解释来源与证据纪律，不持有授权按钮。

## 3. 候选计划：唯一决策面

计划页按以下顺序呈现：

1. 只读事实条：变更引用、摘要、默认阻断范围、对账状态、来源与新鲜度。
2. 摘要：`N 项阻断 + M 项观察 · K 项影响未覆盖`。
3. 影响面缺口：声明外实体使用 amber 卡片，与“将执行的检查”物理分区。
4. 可选观察：不阻塞执行；只有已批准来源的候选可加入。
5. 将执行的检查：展开后显示实体、黄金指标、规则、时间窗、失败动作与来源。
6. 唯一主按钮：`确认并开始巡检`。

### CHG-84501 的边界行为

- 默认阻断范围：`payment-api`。
- `settlement-db`：声明外影响，有已批准的连接池规则，可由用户显式加入。
- `invoice-worker`：声明外影响，无可信直接规则，不提供加入按钮。
- 用户不加入时，计划仍可执行，但报告必须保留未覆盖风险。
- 用户加入 `settlement-db` 后，它才进入锁定 Revision，并可能改变门禁裁决。

禁止文案：“已扩大巡检范围”。发现影响不等于已经覆盖。

## 4. 报告：裁决与覆盖边界同框

报告首屏只有一个视觉高潮：行动建议。右侧/下方紧邻覆盖徽标，例如：

```text
建议暂停在 25% 灰度
覆盖：3 项已验证 · 1 项未覆盖
```

后续固定分层：

- 证据结论与行动决策；
- 数值证据和门禁趋势；
- 逐项检查结果；
- AI 解读：发生了什么 / 可能原因 / 建议动作，每句绑定锁定 evidence ID；
- 结论边界与“未覆盖 / 残余风险”；
- RC Agent 下钻、保存、历史、分享与导出。

`Verified` 只能说明锁定范围通过。只要仍有 coverage gap，报告不得暗示整次发布已全量覆盖。

## 5. 权限与状态

| 动作 | 平台 | Agent | 用户 |
|---|---|---|---|
| 解析变更、拓扑和指标 | 确定性查询 | 解释歧义 | 歧义时补充 |
| 生成默认检查 | 已批准规则与目录 | 给来源和理由 | 无需逐项配置 |
| 加入声明外检查 | 校验来源权威 | 只能推荐 | 显式加入 |
| 锁定并执行 | `PLAN_CONFIRMED` 后原子创建 Revision/Run | 不得改裁决 | 一次确认 |
| 诊断 | 提供锁定证据 | 生成有边界的解释 | 决定后续处置 |

正常首访中，`INPUT_CONFIRMED`、`SCOPE_ACCEPTED` 和 Playbook 专属确认都不是用户可见状态，也不能创建 Run。

## 6. 390px 响应式

- 首页：变更引用全宽置顶，输入与按钮命中区至少 44px；补充说明折叠。
- 计划：事实条 → 影响面缺口 → 可选观察 → 检查列表 → sticky CTA，全部单列且无横向溢出。
- 缺口卡：“加入本次检查”按钮全宽；无可信规则的卡片不出现伪按钮。
- 报告：覆盖徽标换行到结论下方；证据卡和 AI 解读单列。
- 右侧 Agent 面板回到文档流，不使用会遮挡 CTA 的全局固定输入框。

## 7. 可验收 AC

- **AC-J1 发布优先**：`CHG-84501` + 可选关注点直接进入候选计划。
- **AC-J2 一次授权**：正常路径只有一个 `PLAN_CONFIRMED`，且只创建一个 Run。
- **AC-J3 不静默扩面**：声明外实体默认只出现在 coverage gaps。
- **AC-J4 权威加入**：只有具备已批准规则的缺口候选可被显式加入。
- **AC-J5 覆盖诚实**：未加入缺口进入锁定报告的 scope statement 与 residual risks。
- **AC-J6 证据双射**：锁定规则、数值证据、趋势、报告、历史与导出同源。
- **AC-J7 复访不分叉**：exact Playbook 与保存任务复用既有 Revision/Run 链路。
- **AC-J8 移动端**：390px 计划、报告、保存和历史无横向溢出，CTA 不被遮挡。
