# 巡检工作台 v2 · 高保真改版设计（终态，非脚手架）

设计：烁烁 ｜ 实现：丢丢 ｜ 检视：山本
范围：在已合入的双入口工作台（首访对话生成 + 复访直跑）之上做厚——**让保存的任务活起来**。
纪律：DESIGN-SIMPLIFY 六条文案纪律全文有效；本规格覆盖全部状态（含空态/异常态/移动端），不留"后续再补"。

## ① 设计立场

**巡检的价值在时间序列里，不在单次快照里。** 一个任务跑五次全绿，比一次全绿可信得多。v2 的主题只有一个：让 SRE 一眼看到"这个任务的历史表现"，让报告能离开产品去社交（分享），让每次执行知道"和上次比变了什么"。

不加的：对话泛化、大屏报表、模板中心——维持"值班工具"定位。

## ② 信息架构变化（只动两处）

```text
首页（复访第一屏）
└─ 已保存巡检
   └─ 任务卡 v2：名字 + 上次结论 + 迷你运行史 + [直跑▶] + [历史]
       └─ 点卡片/历史 → 任务详情页（新）
            ├─ 运行历史时间线（每次执行一条）
            ├─ 点任意一次 → 该次报告只读快照
            └─ [直跑▶] 常驻顶部

报告页（执行终点）
├─ 新增「与上次相比」区（仅当该任务有历史执行）
└─ 新增「分享」次级按钮 → 导出单文件报告 / 复制摘要文本
```

对话框、五阶段流、Playbook 匹配卡——**零改动**。

## ③ 任务卡 v2（首页）

```text
┌────────────────────────────────────────────┐
│ 履约发布后巡检                      [直跑 ▶] │
│ ●●●●○  最近 5 次 · 上次 Proceed · 2 小时前  │
└────────────────────────────────────────────┘
```

- **迷你运行史**：最多 10 个圆点，色即结论（绿 Proceed / 红 Pause / 灰 未执行），最新在右。hover 显示该次时间与结论。超过 10 次取最近 10 次。
- 卡片整卡可点 → 任务详情；`直跑` 是卡内唯一按钮（CTA 纪律不变）。
- **空态**（从未执行）：圆点区显示一行灰字"还没有执行记录"。
- **异常态**（历史数据损坏/读不出）：卡片正常可直跑，圆点区显示"历史暂不可用"——**损坏的历史不阻塞直跑**，fail open 在执行、fail closed 只在证据。

## ④ 任务详情页（新页面，不新开心智）

```text
┌──────────────────────────────────────────┐
│ ← 返回   履约发布后巡检         [直跑 ▶] │
│ 创建于 8/16 · 共执行 12 次               │
├──────────────────────────────────────────┤
│ 运行历史                                 │
│ ● 8/22 14:00  Proceed   4 项验证通过 →  │
│ ● 8/21 09:30  Pause     连接池超门禁  →  │
│ ● 8/20 22:15  Proceed   4 项验证通过 →  │
│ ...（每条 = 时间 + 结论色点 + 一句话结果）│
└──────────────────────────────────────────┘
```

- 每条历史项可展开 → 该次**报告只读快照**（复用报告渲染，顶部加一条"历史快照 · 2026-08-21 09:30 · 不可修改"提示条）。
- 历史报告**没有**分享/保存按钮——分享只属于最新报告，防止旧结论被当成现状转发。
- 分页：超过 20 条折叠为"显示更早"。

## ⑤ 「与上次相比」区（报告页新增）

位置：行动结论大卡之下、证据分区之上。仅当同一任务存在上一次执行时渲染。

```text
与上次相比（8/21 09:30 → 本次）
✓ 连接池占用：96% → 41%（门禁 80%，已恢复）
→ 支付成功率：持平
+ 新增覆盖：invoice-worker 延迟
```

- 三种行态：`✓ 改善` / `✗ 恶化` / `→ 持平` / `+/- 覆盖变化`。只列**发生变化的**检查项 + 一行汇总；全部持平时整个区收缩为一行"与上次结论一致"。
- 对比基准 = 同一保存任务的上一次执行；首跑不渲染此区（无就是没有，不编造）。

## ⑥ 报告分享

报告页结论卡右下一个次级 ghost 按钮 `分享`：

- **复制摘要**：纯文本五行（结论/时间/任务名/关键证据 Top2/结论边界），贴进 IM 即可读。
- **导出报告**：单文件 HTML（自包含，离线可开），文件名 `任务名-20260822-1400.html`。
- 两个动作都给一行 toast 确认，无弹窗无庆祝。

## ⑦ 移动端（390px）终态

- 任务卡：迷你运行史保留（圆点是最省空间的历史表达），直跑全宽。
- 任务详情：单列；历史项 tap 展开内联快照，不跳页。
- 「与上次相比」：行态图标 + 一行文字，单列堆叠。
- 分享：底部抽屉二选一（复制摘要 / 导出）。
- 底部输入条与详情页返回键互不遮挡（z-index 与 safe-area 已在现有框架内）。

## ⑧ 数据契约（与丢丢对齐，不越界）

- **Run 集合是唯一真相源**：`library.savedInspections[] + library.runs[]` 两个不可变集合保持现状，`SavedInspectionDefinition` **不增加任何持久字段**。
- 历史归属由 selector/ViewModel 派生：`run.definitionId === definition.id`（或 `run.id === definition.sourceRunId`），按 `completedAt` 倒序生成运行历史、迷你圆点与趋势对比基准。
- `InspectionRun` 新增可选的不可变 `executionResults[]` 快照（`id / label / status / fact`）；新 Run 必须写入，旧 Run 缺失时只降级隐藏逐项趋势，不影响历史报告与直跑。趋势比较只读取结构化执行结果，不解析报告文案。
- localStorage mock 继续承担持久化，界面保留"本地 mock"徽标；未来接服务端时改为按 `definitionId` 查询/索引，UI 契约零改动。
- 修正记录：初版 §⑧ 曾提议向 Definition 追加 `runs[]` 持久字段，丢丢指出其破坏定义不可变并造成双真相，已采纳派生方案（2026-08-22）。实现核对又确认现有 Run 只有聚合报告、没有逐检查结果；为避免解析展示文案伪造趋势，新增可选不可变执行快照，Definition 仍零变更（2026-08-23）。

## ⑨ 可验收 AC

- **AC-V1 迷你运行史**：执行 ≥2 次后任务卡出现色点时间线；hover 有详情；0 次显示"还没有执行记录"。
- **AC-V2 详情页**：历史列表完整、倒序、每条可展开只读快照；快照无保存/分享按钮，有"历史快照"提示条。
- **AC-V3 趋势对比**：同一任务第二次执行后报告出现"与上次相比"；变化项三种行态正确；全部持平时收缩为一行；首跑不出现此区。
- **AC-V4 分享**：复制摘要为可读五行文本；导出为自包含单文件 HTML，断网可开、内容与本页一致。
- **AC-V5 异常不阻塞**：mock 损坏历史数据，直跑可用、圆点区降级提示。
- **AC-V6 审计纪律**：所有历史报告只读；任何路径不能修改历史 Run。
- **AC-V7 移动端**：390px 全流程（直跑→报告→对比→分享→详情）无横溢、无遮挡。
- **AC-V8 文案纪律**：AC-S1 禁用词清单为零；新增界面无口号、无英文装饰标签。
