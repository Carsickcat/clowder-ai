# 报告页 v2 · 生成与解读深化（设计规格 · 终态）

触发：co-creator“巡检报告的生成和解读还有一点简陋”。
设计：烁烁 ｜ 实现：丢丢 ｜ 文案纪律：DESIGN-SIMPLIFY 六条继续有效。
定位：报告是**裁决书**——读完能拍板、能下钻、能转发。不是数据堆砌。

## ① 诊断：现在简陋在哪

| 现状 | 问题 |
|---|---|
| 关键证据是纯文本列表 | “连接池占用 96%（门禁 80%）”是一句话，数值和门禁的关系要靠人脑解析 |
| 没有逐项检查总表 | 4 项检查各自的通过/违例状态散落在摘要里，看不到全貌 |
| AI 解读 = 一行 summary | “模型分析总结的风险项”（co-creator 原始诉求）没有真正落地 |
| 报告无元信息头 | 没有任务名/执行窗口/耗时/实例号，转发出去别人看不懂上下文 |

## ② 改版后报告结构（自上而下）

```text
┌ 报告头（新）：任务名 · 执行时间 · 数据窗口 · 实例号 · 耗时 ┐
├ 结论大卡（保留）：行动结论 + 一句话理由 + 复制/导出        ├
├ 与上次相比（保留，不变）                                   ├
├ 证据仪表盘（新·替换成文本列表）：                           │
│   每项关键证据 = 数值卡：                                  │
│   指标名  当前值  门禁值  [██████░░] 状态点                │
├ 检查结果总表（新）：每项检查一行                            │
│   状态点 · 检查目的 · 对象 · 实际值 vs 门禁 · 可展开细节     │
├ AI 解读（新·替代一行 summary）：三段式                     │
│   发生了什么 / 可能原因 / 建议动作（每条挂证据锚点）         │
├ 结论边界 + 残余风险（保留）                                 │
├ RC Agent 抽屉（保留，异常旅程）                             │
└ 保存方案区（保留）                                          ┘
```

## ③ 三个新区块的规格

### 证据仪表盘（把字符串变数据）

每个证据项从字符串升级为结构：

```text
┌──────────────────────────────────────────┐
│ 连接池占用                          ● 违例 │
│ settlement-db                            │
│ 96% ━━━━━━━━━━━━━━━━━━━█░░ 门禁 80%      │
└──────────────────────────────────────────┘
```

- 数值大字 + 门禁值小字 + 一条占比条（当前值/门禁刻度），状态色点收尾。
- 无法数值化的证据（如“无新增错误 Trace”）显示为 ✓/✗ 行，不强行画条。
- 排序：违例置顶，未决其次，通过最后。异常一眼浮上来。

### 检查结果总表

- 每项执行过的检查一行：状态点（✓/✗/?）+ 目的 + 对象 + 实际值 vs 门禁（如 `68ms / ≤20ms`）。
- 默认折叠为一行，点开展开完整六字段（复用草案页的展开交互）。
- 计数胶囊（✓4 !1 ?0）保留在该区标题行。

### AI 解读三段式（“模型风险总结”的正位）

```text
AI 解读
发生了什么：settlement-db 连接池占用 96%，已超 80% 门禁。  [证据①]
可能原因：共享配置包将连接池上限从 120 降为 60。          [证据②]
建议动作：暂停灰度，恢复连接池上限后复验。                [转 RC Agent]
```

- 每条陈述右下角挂证据锚点（点击高亮对应证据卡）。
- **诚实红线**：无充分证据的段落直接写“证据不足”而不是编故事；AI 解读永远不改写证据结论。

## ④ 报告头

一行元信息条：`履约发布后巡检 · 2026/8/29 14:00 · 窗口 变更后15分钟 · 实例 INS-0049 · 耗时 42s`。
导出 HTML 和复制摘要都带上这行——离开产品后上下文不丢。

## ⑤ 不动的部分

结论大卡、与上次相比、结论边界/残余风险、RC 抽屉、保存方案、分享动作——全部保留原位。本轮是**深化证据与解读**，不是推翻布局。

## ⑥ 移动端

证据卡单列堆叠；检查总表行内展开；AI 解读三段保持顺序。占比条最小宽度 120px 不截断数值。

## ⑦ 可验收 AC

- **AC-R1** 报告头元信息条存在且导出/复制的摘要中包含同样信息。
- **AC-R2** 证据仪表盘中数值型证据显示当前值、门禁值、占比条与状态点；违例排在最前。
- **AC-R3** 检查总表覆盖全部已执行检查，每行含状态+实际值/门禁；可展开六字段。
- **AC-R4** AI 解读为三段式，每段挂证据锚点且锚点可定位高亮；无证据支撑的段落显示“证据不足”。
- **AC-R5** 异常旅程（Violated+Pause）下违例证据卡红色置顶，RC 抽屉可达。
- **AC-R6** 历史快照渲染同样结构但标注“历史快照·不可修改”，且无分享/保存。
- **AC-R7** 390px 无横溢，占比条不截断。
- **AC-R8** 文案纪律：零口号、零新英文装饰标签；“AI 解读”区不得出现任何无证据锚点的断言。
