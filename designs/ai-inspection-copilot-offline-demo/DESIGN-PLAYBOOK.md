# 场景巡检方案（Inspection Playbook）复用 · 高保真设计包

设计负责人：烁烁 ｜ 实现负责人：丢丢 ｜ 基线：NOVA 巡检 Copilot 离线 Demo（五阶段状态机 + 深色工作台）
边界遵守：本包只新增设计规格，不修改现有代码；不另造独立模板 dashboard；历史任务实例永不可变。

## ① 核心设计立场

**方案是加速器，不是入口。**

SRE 的心智起点永远是"我现在有个事要查"，不是"我去方案库逛逛"。所以：

1. **空白发起入口保持第一公民**。Playbook 不以 dashboard、列表页、模板中心任何形式抢入口——它只在系统识别出"这个场景我见过"时，以一张**匹配卡**出现在决策路径上。
2. **匹配卡是提议，不是劫持**。用户可以一键采纳，也可以无视它继续空白生成；无视行为本身是反馈信号（计入方案质量数据）。
3. **复用的是"判断结构"，不是"旧数据快照"**。从方案发起 = 继承 Check 清单、判定规则、影响面假设，但证据、基线、对账全部现场重跑。界面上必须让"这是新证据、老框架"一目了然——这是审计不可变性在视觉层的投影。
4. **AI 的存在感在差异里**。精准匹配时 AI 几乎不说话（说话就是噪音）；差异越大，AI 的解释越靠前。信息量与不确定性成正比。

Push back 记录：丢丢的三条边界（不做 dashboard 入口 / 不重放快照 / 不牺牲空白入口）我全部接受，无反对意见——它们和我的立场同构。

## ② 五状态 × 状态流

```text
intake（输入理解）
   │  场景识别完成，触发方案匹配（mock：按场景 key 命中）
   ▼
context（范围对账）── 顶部新增「方案匹配卡」，五态互斥：
   │
   ├─ S1 无匹配      → 不出现卡片，流程与现状完全一致（零打扰）
   ├─ S2 精准匹配     → 卡片绿态，主 CTA「按方案直跑」
   ├─ S3 小幅差异     → 卡片 amber 态，主 CTA「确认差异并继续」
   ├─ S4 重大漂移     → 卡片红态，主 CTA「重新生成」，方案降级为右侧参考面板
   └─ （S5 见下，发生在 report）
   ▼
plan → execution → report（既有五阶段不变）
   │
   └─ S5 执行完成    → report 页新增次级 CTA 区：
                       无方案来源 →「保存为新方案 v1」
                       有方案来源 →「提交方案更新 v(n+1)」（需审批态标记）
```

**关键约束**：S2 直跑不等于跳过对账——Change Reconciliation 仍强制执行，只是计划草案预填、人工确认点从"逐条审"降为"一次确认"。护栏不因为熟路而拆除。

## ③ 布局与交互规格

### 方案匹配卡（唯一新核心组件，位于 context 阶段顶部）

```text
┌──────────────────────────────────────────────────────────────┐
│ ◆ 命中方案  支付配置变更巡检 · v3          [匹配 96%] [3天前] │
│ ├─ S2 绿：证据框架仍有效，实体/指标/依赖/权限/模板五项校验通过 │
│ │   [按方案直跑 ▶]            [不用方案，重新生成]（文字链）   │
│ ├─ S3 黄：2 项差异需要你确认                                   │
│ │   ▸ 依赖变化：settlement-db 新增只读实例（方案 v3 之后）     │
│ │   ▸ 指标漂移：支付成功率口径 v2 → v3                         │
│ │   [确认差异并继续]           [不用方案，重新生成]            │
│ └─ S4 红：场景已发生重大漂移，方案 v3 不再适用                 │
│     ▸ 核心服务拆分：payment-api → payment-api + risk-api       │
│     ▸ 3 项关键检查无对应实体                                   │
│     [重新生成（参考旧方案）]                                   │
└──────────────────────────────────────────────────────────────┘
```

- **三信号一目了然**：匹配度百分比、最后使用时间、差异条数——扫一眼即可决策，不展开不读细节。
- **差异表达用 chips 不用表格**：每条差异 = 维度标签（依赖/指标/实体/权限/模板）+ 一句人话 + 方向（新增/消失/变更）。继承 `.entity-cloud` 的视觉语言。
- **展开惰性**：S2 默认折叠全部校验细节（"五项校验通过 ▾"可展开）；S3 默认展开差异 chips；S4 默认展开且锁定必须看完才能点 CTA。
- **CTA 层级纪律**：每张卡只有一个实心主按钮；替代路径一律文字链。S4 的"重新生成"点击后旧方案缩为右栏参考卡（复用右栏 Copilot 面板槽位），不占据主路径。

### report 阶段 S5 保存/更新区

```text
┌─ 方案沉淀 ─────────────────────────────────────┐
│ 本次任务已沉淀为不可变实例 #47（审计锁定）        │
│ [保存为新方案]            ← 无方案来源时（次级按钮）│
│ [提交方案更新 → v4 · 待审批] ← 有方案来源时       │
│ 说明：更新不改变历史实例，审批通过后下次匹配生效    │
└─────────────────────────────────────────────────┘
```

位置在 RC Agent 区之上、结论卡之下——**先让 SRE 看完结果，再谈沉淀**。CTA 永远次级（ghost 按钮），因为沉淀是好习惯，不是当务之急。

## ④ 现有 token / 组件复用映射

| 新元素 | 复用 | 说明 |
|---|---|---|
| 匹配卡容器 | `.prompt-card` + `.reconciliation` | 同款卡片描边与内边距 |
| S2/S3/S4 状态色 | `--green` / `--amber` / `--red` + `*-soft` 底 | 与证据语义色完全一致，S2 绿 = "已验证可继续"的家族色 |
| 匹配度/时间/差异数 | `.readiness` 胶囊 | 直接复用证据胶囊样式 |
| 差异 chips | `.entity-cloud` 标签 | 维度标签着色用 `--blue`/`--amber`/`--red` |
| 主 CTA | `.compile-button` | 同款实心按钮 |
| 参考面板（S4 降级态） | 右栏 `.module-tag` 面板 | 复用右栏槽位，零新布局 |
| 保存/更新按钮 | ghost 按钮（`.example-fill` 风格） | 次级存在感 |
| 新增 token | 无 | **零新增色值**——五态全部落在现有语义色上 |

## ⑤ 移动端规格（≤768px，390px 基线）

- 匹配卡降为**全宽横幅条**：一行结论（"命中方案 v3 · 2 项差异"）+ 一个主按钮；差异详情收进**底部抽屉**（bottom sheet），点"查看差异"上滑展开。
- S4 红态在移动端同样强制看完差异才解锁 CTA——抽屉必须滚到底。
- report 的保存/更新区跟随后置内容自然流式排列，按钮全宽堆叠。
- 复用现有 `responsive.css` 单列降级规则，匹配卡不引入任何横向滚动。

## ⑥ 可验收 AC（实现验收基准）

- **AC-P1 零打扰**：无匹配场景（S1）的 DOM 与现有版本逐像素一致，不出现任何方案相关元素。
- **AC-P2 精准直跑**：S2 状态下点击"按方案直跑"，Check 清单预填且 Reconciliation 仍执行；一次确认即可进入 execution。
- **AC-P3 差异确认**：S3 状态展示 ≥1 条维度化差异 chip；确认后计划草案反映差异（新增实体进入影响面），且该确认动作进入任务实例记录。
- **AC-P4 漂移拦截**：S4 状态下不存在"直跑"路径；强制重新生成，旧方案仅以参考面板出现；移动端需滚动看完差异。
- **AC-P5 审计不可变**：从方案发起的执行生成**新任务实例**（新 ID、新证据包）；任何路径都不修改历史实例；保存/更新方案只产生新版本，旧版本可回溯。
- **AC-P6 空白入口主权**：intake 页空白发起路径与现状一致；匹配卡所有状态都提供"不用方案"文字链出口。
- **AC-P7 移动端**：390px 视口匹配卡降级为横幅+底部抽屉，无横向溢出；五态均可完整走通。
- **AC-P8 状态纯净**：切换场景/重新发起时，方案匹配状态随 reducer 重置，不串状态（与现有场景重置契约同款测试）。
