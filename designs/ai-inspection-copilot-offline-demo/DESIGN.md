# AI 巡检 Copilot 离线产品 · 高保真设计规格

设计负责人：烁烁（视觉/交互）。本文件是已实现界面的视觉真相源：后续任何改版以此为准对齐，不允许凭感觉改色值与层级。

## 设计目标

SRE 第一次打开页面的 3 秒内必须知道：**我可以直接描述自己的巡检目标。** 生成报告后，3 秒内必须回答：**我现在该做什么？**

因此产品入口向“用户定义”倾斜，报告向“行动结论”倾斜。示例只能降低空白页启动成本，不能成为一级产品模式。

## 信息架构（决策路径，非检查项列表）

```text
新建巡检工作区
├─ 自由目标输入（主入口）
├─ 目标服务（可选消歧）
├─ 电子流 / 发布单（可选事实补全）
└─ 可编辑示例（只填充，不切换模式）
生成后的决策视野（一屏内必须同框）
├─ ACTION FIRST 大结论卡：Proceed / Pause / Rollback + 一句人话理由
├─ 二维裁决双卡：证据结论（系统知道了什么）｜行动决策（SRE 该做什么）
├─ 证据胶囊聚合：✓已验证 / !违例 / ?未决（只计数，不逐条刷屏）
├─ 关键证据 + 结论边界 + 残余风险（并排双卡）
└─ RC Agent 抽屉（仅异常结果可用）
左侧栏：输入理解 + 变更对账（Change Reconciliation 状态卡）
右侧栏：Copilot 状态 + 结论边界提示 + 护栏（不生成任意查询 / 不把缺失写成正常 / 不代替 SRE 执行）
顶部：单一产品标题 + 五阶段进度（输入理解→范围对账→任务草案→执行取证→行动报告）
```

## 设计 Token（已实现于 src/tokens.css）

| 角色 | 值 | 用途 |
|---|---|---|
| `--bg` | `#07101f` | 深海军蓝底，配双径向渐变光晕 |
| `--surface` | `rgba(14,29,51,.88)` | 卡片浮层 |
| `--cyan` `#5ae7d2` | 主强调 | 进度、链接、焦点环、品牌 |
| `--green` `#72e6a6` | Verified / Proceed | 证据通过、放行 |
| `--red` `#ff6d7f` | Violated / Pause | 违例、暂停（大结论卡红色渐变描边） |
| `--amber` `#f6ba5b` | Inconclusive / 候选 | 未决、待处置 |
| `--blue` `#6d91ff` | 信息 / 对账 | Change Reconciliation、RC 链 |
| 字阶 | 大结论 30px+ 粗体，正文 14px | 结论永远最大 |
| 圆角 | 10 / 16 / 24 | 胶囊 / 卡片 / 大结论卡 |

**语义色纪律**：绿=证据已验证且可继续，红=证据违例需停， amber=不知道。Unknown/Inconclusive 永不允许渲染成绿色——这是信任红线，不是审美偏好。

## 关键交互契约

1. **空态是一等状态**：首次打开为空白工作区；未提交用户目标前，不预选任何 scenario，也不渲染范围与计划。
2. **示例不是模式**：示例按钮只能填充表单，用户可编辑；点击示例不得创建工作区或改变导航。
3. **候选阻断可视化**：高关键度 AI 候选未处置时，"确认任务"按钮禁用，且候选项自带"纳入计划/忽略"处置动作。
4. **二维呈现**：用户首屏只见行动态；证据态以胶囊聚合计数呈现，二维细节只出现在下钻层。
5. **护栏常驻**：右栏固定展示三条安全边界，让"AI 不越权"可见而非隐式。
6. **移动端**：≤768px 降单列，390px 无横向溢出（浏览器验收钉住）。

## 与方案的映射

本设计同时实现两条原则：入口是“用户定义巡检”，报告是“裁决书”。产品不替用户挑场景；系统只把用户目标编译成可审阅、可执行、可追溯的工作区。
