# 设计把关：从"发布会海报"到"值班工具"（简洁化改造规格）

发起人：co-creator（"每次点击下一步都有很多标语式的口号，不像可用产品"）｜ 把关：烁烁 ｜ 实现：丢丢
优先级：**高于一切新功能**。这是设计负责人认领的还债——我之前审的是"理念是否被表达"，漏审了"理念是否喊得太响"。

## 把关立场

**工具的第一美德是闭嘴。** SRE 打开它是来干活的，不是来听布道的。理念（证据/行动分离、不静默猜测、确定性引擎边界）应该体现在**行为**里，而不是印在每一屏的标题上。一屏只说一件事，说事不说理念。

## 文案纪律（六条硬规则）

- **R1 标题 = 功能短语**。名词或动宾，≤8 字。禁止判断句、禁止成果汇报句。"多源事实已经对齐"不是标题，是邀功。
- **R2 宣言句零容忍**。"不是 X 而是 Y"、"我只保留…"、"确定性引擎产生证据；Copilot 只…"——全部删除，不迁移、不折叠、不换位置。理念已经刻在状态机里，不需要刻在用户视网膜上。
- **R3 同一信息只说一次**。"复用的是检查结构…证据将重新采集"在每张方案卡重复出现——保留唯一一处（S2 exact 卡），且压缩为 hover tooltip。
- **R4 消灭英文装饰标签**。`MODULE 01 · INPUT COMPILER`、`BLAST RADIUS`、`ACTION FIRST`、`PLAYBOOK LEARNING LOOP`、`SCOPE RESOLVER`——全部删除或替换为中文功能标签。它们只服务"看起来很专业"，不服务理解。
- **R5 护栏/判断降级为脚注**。右栏"当前判断""护栏"三条每屏常驻 → 收成页脚一行小字 + 一个 ⓘ 图标（hover 展开）。护栏的可信来自行为，不来自复读。
- **R6 一段话不超过一行**。卡片内说明文字 >40 字的一律砍到一行；砍不动的说明它本该是结构化字段，不是散文。

## 逐屏改造映射（Before → After）

### intake 输入理解
| 现状 | 改为 |
|---|---|
| "从一句话生成一份值得 SRE 确认的巡检任务" | **删除**（页面功能已自明） |
| "先确认我理解得对不对" | "确认变更信息" |
| "实体不唯一或缺少版本时，我不会静默猜测。" | **删除**（行为已体现：缺字段就不生成） |
| MODULE 01 · INPUT COMPILER | 删除 |

### context 范围对账
| 现状 | 改为 |
|---|---|
| "多源事实已经对齐" + 整段"不是把图谱上的所有关系塞进任务…" | "确认巡检范围"，副标题删除 |
| "范围不是知识图谱全展开 / 我只保留业务目标…"（右栏） | **删除** |
| BLAST RADIUS · 本次影响面四维视图 | "影响面" |
| 四张来源卡各带"新鲜度"散文 | 保留卡片，每卡说明砍至一行 |

### 方案匹配卡（Playbook）
| 现状 | 改为 |
|---|---|
| "当前事实与已审批方案一致" | "命中方案：订单发布后验证 v4" |
| "证据框架仍有效，五项现场校验全部通过" | "五项校验通过 ▾"（保留展开） |
| "复用的是检查结构；实体、指标、Trace…证据将重新采集。"（每态重复） | 仅 S2 保留，收成 ⓘ tooltip；S3/S4 删除 |
| "旧方案不再适用 / 场景边界已改变，旧方案只能作为重新生成的参考" | "方案 v3 不适用：2 项重大差异" |

### plan 任务草案 / execution 执行取证
| 现状 | 改为 |
|---|---|
| "候选不是正式任务"（宣言式标题） | "高风险候选 · 待处置"（状态即事实） |
| "完成执行并生成报告" 等阶段口号 | "执行检查" |
| 每个执行步骤的散文说明 | 一行：检查名 + 结果 + 门禁值 |

### report 行动报告
| 现状 | 改为 |
|---|---|
| ACTION FIRST · PROCEED kicker | 删除（大卡配色已表达状态） |
| "确定性引擎产生证据；Copilot 只组织理由和下一步。" | **删除** |
| PLAYBOOK LEARNING LOOP · 方案沉淀 + 说明段 | "保存方案"，说明一行："历史实例不受影响" |
| "结论有边界"（右栏重复） | 删除右栏重复，报告正文保留结论边界卡 |

### 全局
- 右栏"可信任务编译器 ONLINE"：改为安静的状态点，不每屏刷存在感。
- 页脚："所有数据均为 mock，不会触发真实生产动作" 保留（这是工具诚实性，不是口号）。

## 视觉密度调整

1. **大标题降级**：除 report 结论卡外，所有阶段标题从 28px+ 降到 18px/600，去掉 hero 渐变底。一个页面只允许一个视觉高潮——最终的行动结论。
2. **卡片去散文化**：所有说明性段落改为一行备注或字段化（标签: 值）。
3. **进度条瘦身**：五阶段 rail 保留，但阶段名已经是最好的文案，不需要每阶段再配一句口号。

## 不动的部分

- 五阶段状态流、三栏/单列布局、语义色纪律、方案匹配卡五态逻辑、CTA 层级——这些是对的，是骨架。本轮只割脂肪，不动骨头。

## 可验收 AC

- **AC-S1**：全站搜索不到以下任一字符串："不是把"、"我只保留"、"确定性引擎产生"、"不会静默猜测"、"值得 SRE 确认"、"MODULE 0"、"BLAST RADIUS"、"ACTION FIRST"、"LEARNING LOOP"。
- **AC-S2**：每个阶段标题 ≤8 个中文字符，且无句号结尾的判断句。
- **AC-S3**：任一卡片内说明文字单行渲染不折行（桌面 1423px 与移动 390px 双侧）。
- **AC-S4**：右栏不再出现"当前判断""护栏"常驻块；页脚保留 mock 声明。
- **AC-S5**：报告页视觉第一层级仍是行动结论大卡（简化后唯一 hero）。
- **AC-S6**：回归——五阶段旅程、方案五态、CTA 门禁行为零变化（纯文案/视觉层改造，41/41 测试应不动或通过最小快照更新）。
