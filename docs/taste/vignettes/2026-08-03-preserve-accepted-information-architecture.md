# Preserve accepted information architecture while deepening product intelligence

## Situation

An operator had already accepted a workbench whose spatial model was easy to remember: historical tasks on the left, selected-task truth in the center, a live copilot workflow on the right, and execution details below. Later iterations were individually polished and runnable, but replaced this model with different shells and made the product feel less coherent.

## Correction

Treat an explicitly accepted information architecture as a product contract. New intelligence belongs inside the existing regions unless a replacement demonstrates a specific, measurable usability gain and receives an explicit direction decision.

For an AI operations workbench, deepen the two value loops rather than adding surfaces:

1. **Generation loop:** intent → governing guide → business graph → explainable checks → dependency-aware execution plan.
2. **Interpretation loop:** immutable evidence → deterministic score → deductions and residual risk → cited plain-language explanation.

## Guardrail

- Freeze the accepted spatial regions and proportions in an experience-contract test.
- Require every new design iteration to name the user problem it improves; “newer” or “more complete” is not an improvement claim.
- Keep AI provenance, confidence, omissions, scoring, and citations visible in the task/report surfaces where the operator already looks.
- When required knowledge is missing, block and explain the omission instead of fabricating a generic plan.

## Evidence

The corrected prototype preserved the original three-column-plus-bottom layout, added a permanent drift contract, and passed offline Chrome journeys across desktop and mobile with no network access, console errors, or horizontal overflow.
