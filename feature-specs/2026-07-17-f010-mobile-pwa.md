# F010 Mobile PWA Implementation Plan

**Feature:** F010 — `docs/features/F010-mobile-cat.md`  
**Goal:** 让 operator 通过 Tailscale 在手机上使用与桌面同源、可安装、好操作且可恢复的 Clowder AI，不复制第二套产品。  
**Acceptance Criteria:**

- AC-A0：形成 390×844、430×932、768×1024、1024×768 的现状证据与路由 × 功能 × 设备矩阵；记录 operator 真机型号和主要摩擦。
- AC-A1：`<1024px` 统一使用移动工作表面；JS 与 Tailwind 消费同一 breakpoint 真相源；左侧抽屉提供 Threads / Memory / Mission / Signals / Settings，底栏保留对话 / 工作 / 产物 / 全局审批。
- AC-A2：安装体验覆盖 secure context、Service Worker、standalone、iOS 手动步骤、支持/不支持/WebView 诊断和本机 30 天 dismiss；API、Socket、上传下载保持 Tailscale HTTPS 同源。
- AC-A3：后台恢复、online/offline、Socket 重连和 Service Worker 更新均有明确状态；更新不会丢失草稿、当前 thread 或已提交业务动作。
- AC-A4：手机核心功能 parity checklist 无缺项；light/dark 与主要主题完成浏览器截图，iPhone/Android 完成关键旅程真机记录，桌面 AppShell 无回归。
- AC-A5：代码通过测试、lint、check、build、浏览器 dogfood，并由 terra、Opus 4.5、Fable 5 给出明确代码 review verdict，P1/P2 清零。

**Architecture cell:** `hub-action-surface`（主）；`thread-navigation`、`approval-index`（相邻消费）  
**Map delta:** none  
**Map delta why:** 本轮只重组既有 Hub、ThreadSidebar 与 ApprovalPanel 的响应式组合，不改变它们的 owner、数据边界、扩展点或 canonical store。  
**Architecture:** AppShell 继续承载单一产品壳；viewport 仅决定组合形态，不复制业务 store。移动全局抽屉复用 ThreadSidebar 和现有全局 route，底栏复用 thread 工作面与全局 Approval Hub。安装与更新逻辑用纯派生状态机包裹浏览器能力，唯一新增持久状态是 30 天 banner dismissal。  
**Tech Stack:** Next.js 14、React 18、TypeScript、Tailwind CSS 3、Vitest、next-pwa/Workbox  
**前端验证:** Yes — focused Vitest + 独立 dev URL 的 Browser Preview + 响应式截图/录屏 + operator 真机记录

## 0. Straight-Line Contract

### Finish line B

operator 从 Tailscale HTTPS 打开同一套 Clowder AI，在手机浏览器和 standalone PWA 中都能完成 thread 选择、召唤、发送、工作、产物、全局审批与全局模块导航；断点、安装诊断、恢复和更新均有可验证状态，桌面无回归。

### Terminal schema

- `ResponsiveBreakpoints`：`compact < 768`、`medium 768..1023`、`wide >= 1024`；Tailwind 与 TypeScript 读取同一 JSON token。
- `GlobalNavigationItem`：`home | memory | mission | signals | settings`，同一 route/referrer resolver 供桌面 ActivityBar 与手机抽屉消费。
- `InstallEnvironment`：secure / online / platform / standalone / service-worker / native-prompt / embedded-webview 的纯事实快照。
- `InstallPresentation`：`hidden | contextual | diagnostic | guide`，由环境、30 天 dismissal 与用户动作派生。
- `ServiceWorkerUpdateState`：`unsupported | current | update-ready | reloading | error`，只描述浏览器 controller 生命周期，不复制 Workbox 状态。

### Not building

- 不做 Capacitor、Swift、React Native 或 Flutter 壳；
- 不新增 mobile API、mobile store 或第二份 thread/message 数据；
- 不做完全离线发送；
- 不修改远程 owner、HTTP/Socket 鉴权或 Tailscale 主机配置；
- 不把 Phase C Push/badge 混入本轮；
- 不修改 `.env`、Redis/SQLite、启动配置或 runtime 实例。

## 1. Stateful Object Census

### 1.1 Responsive layout（纯投影，零存储）

Owner：`useIsDesktop` + Tailwind screen token。输入只有 viewport；禁止写 localStorage 或单独 store。

| 当前状态 | 事件 | 下一状态 | 行为 |
|---|---|---|---|
| compact | width >= 768 | medium | 保持移动工作表面，可增加密度 |
| medium | width < 768 | compact | 保持移动工作表面 |
| medium | width >= 1024 | wide | 切桌面 AppShell，关闭移动 overlay |
| wide | width < 1024 | medium/compact | 切移动 AppShell，关闭桌面 resize surface |

### 1.2 Install experience

Owner：AppShell 下唯一 `PwaInstallExperienceProvider`。持久化仅允许 `dismissedUntil`，不得存 `beforeinstallprompt` event、standalone 或 support facts。

| 状态 | 事件 | 下一状态 | 行为 |
|---|---|---|---|
| hidden | eligible + dismissal expired | contextual | 展示一次不遮挡的 banner |
| contextual | dismiss | hidden | 写 `dismissedUntil = now + 30d` |
| contextual/guide | native prompt accepted | hidden | 清 event，等待 `appinstalled`/standalone |
| contextual/guide | native prompt rejected/error | guide | 保留准确手动说明，不伪报成功 |
| any | standalone/appinstalled | hidden | 清 prompt 与 sheet |
| any | insecure/WebView/unsupported | diagnostic | 仅常驻入口可打开诊断；不展示“立即安装” |
| any | online/offline/visibility change | derived | 重算事实，不持久化派生状态 |

旁路禁止：组件不得自行写第二个 dismissal key；不得用 user-agent 单独宣称 installable；不得在 desktop/standalone 显示 contextual banner。

### 1.3 Service Worker update

Owner：AppShell 下唯一 `PwaUpdateController` 与常驻 `PwaTransientWorkGuard`。无新增持久 store；文字/引用继续写既有 sessionStorage，附件与审批瞬态只作为 reload veto。

| 状态 | 事件 | 下一状态 | 行为 |
|---|---|---|---|
| unsupported | mount | unsupported | 不展示虚假更新 UI |
| current | `registration.waiting` | update-ready | worker 保持 waiting，显示非静默的更新提示 |
| update-ready | user confirms + guard allows | reloading | 发送 `SKIP_WAITING`，等待新 controller |
| update-ready | guard veto | update-ready | 保留 waiting worker 与提示，不激活、不 reload |
| reloading | `controllerchange` | reloading | 只 reload 一次 |
| update-ready | route/background change | update-ready | 保留提示，不自动丢上下文 |
| any | registration/update error | error | 给可重试提示，不循环 reload |

### 1.4 Invariants

- **INV-1**：`isDesktop` 与 `lg:*` 在 1024px 同时切换；768–1023 不出现桌面 sidebar + 移动底栏双态。
- **INV-2**：移动抽屉关闭后只保留一个主工作表面；ESC/overlay/back 优先关闭 overlay。
- **INV-3**：审批 badge 与列表读取全局 Approval Hub；当前 thread 只是可选过滤，不改变全局 count。
- **INV-4**：contextual install banner 在 dismiss 后 30 天内不重弹；常驻安装/诊断入口仍可手动打开。
- **INV-5**：非 secure、WebView、不支持、offline 或 manifest 404/HTML 场景不得出现可执行“立即安装”。
- **INV-6**：standalone 与 `appinstalled` 后 banner/sheet 均隐藏。
- **INV-7**：新 Service Worker 在用户确认前保持 waiting；所有 thread 草稿/附件、审批 selection/deciding 或 storage 写失败都会阻止激活，确认后 controller 变化只 reload 一次。
- **INV-8**：API、Socket、uploads/downloads 不被 Service Worker 作为陈旧业务响应返回。
- **INV-9**：任何移动组合层不得新增 thread/message/task/artifact/approval 持久 store。

### 1.5 Adversarial matrix

- 767 ↔ 768 ↔ 1023 ↔ 1024 连续 resize；overlay 打开时跨断点；横屏 1024×768；
- dismiss 后刷新、改系统时间、localStorage 损坏、storage unavailable；
- `beforeinstallprompt` 先到/后到/重复到、prompt reject、prompt throw、`appinstalled` 与 display-mode change 乱序；
- raw HTTP、Safari、Android Chrome、内嵌 WebView、无 Service Worker、offline；
- waiting worker 在非当前 thread 有附件、composer/审批面已卸载、storage 写失败、审批 selection/deciding 时到达；均不得激活；重复 controllerchange 不得 reload loop；
- 切 thread 时旧 reconcile 请求晚到，不能覆盖新 thread 状态（复用既有 generation guard）。

## 2. Design-in-Context Record

- 已读目标组件：`AppShell.tsx`、`ActivityBar.tsx`、`ChatContainer.tsx`、`ChatContainerHeader.tsx`、`ThreadSidebar.tsx`、`MobileOpsShell.tsx`、`ApprovalPanel.tsx`、`PwaInstallPrompt.tsx`。
- 现有元素：桌面 ActivityBar、桌面 ThreadSidebar、手机 thread overlay、手机状态 sheet、手机四项底栏、Concierge、Presentation float、候选安装 banner/sheet。
- 新能力性质：用统一手机全局抽屉替换仅含 ThreadSidebar 的手机 overlay；复用而非复制桌面全局 route；补充安装诊断/更新状态。
- canonical 位置：顶部 `☰` 打开左侧全局抽屉；安装常驻入口在抽屉底部；contextual banner 只在符合条件时出现。
- 备选否决：继续显示 52px ActivityBar 会挤压手机主表面且与 `☰` 双入口；把全局模块塞进底栏会与 thread 工作闭环争位。
- 密度策略：compact/medium 都是单主表面；medium 只放宽抽屉和内容 padding，不切桌面三栏。
- 状态覆盖：loading/empty/error 继承各业务组件；install/update 新增 unsupported/diagnostic/error；light/dark 复用 token。
- 视觉冲突：overlay z-index 必须低于安装 sheet/系统 modal、高于聊天；所有颜色、边框、阴影复用 Console token。
